จุดประสงค์การเรียนรู้

จบ EP นี้แล้วผู้เรียนจะ

  1. อธิบายได้ว่า Physical AI ต่างจาก AI ที่ทำงานกับข้อความอย่างไร: intelligence บวกกับร่างกาย
  2. แยกเครื่องกล (automaton) ที่ขยับตามลำดับเดิม ออกจากหุ่นยนต์ที่รับรู้แล้วปรับตัว
  3. มองหุ่นยนต์ทุกตัวเป็นวงจร sense → think → act และบอกได้ว่าแต่ละขั้นของ Microduck คืออะไร
  4. อธิบายว่าทำไมการเดินจึงยากสำหรับหุ่นสองขา และเลือกได้ว่างานไหนควรใช้กฎ, control หรือการเรียนรู้
  5. ใช้ Python, NumPy และ Git บน Colab แล้วเก็บงานขึ้น GitHub ได้
  6. เปิด model ของ Microduck ใน MuJoCo อ่าน joint, motor และ sensor ของมัน และแสดงได้ว่าการค้างท่าไม่ใช่การทรงตัว

เป็ดที่ล้มในไม่ถึงวินาที

AI แต่งกลอนให้เราได้ในไม่กี่วินาที แต่ Microduck หุ่นเป็ดสูงราว 25 cm ที่ถูกสั่งให้ค้างท่ายืนใน simulator แล้วปล่อย ไม่ถึงวินาทีก็ล้มนอนอยู่บนพื้น ถ้า AI เก่งภาษาขนาดนั้น ทำไมพอมีร่างกาย แค่ยืนให้อยู่ก็ยากแล้ว? วิชานี้เริ่มจากคำถามนี้ และจบที่เป็ดตัวนี้เดินได้เอง

Physical AI: AI ที่มีร่างกาย

AI ส่วนใหญ่ที่เราใช้รับข้อมูลเข้าแล้วส่งข้อมูลออก ส่วน Physical AI มีร่างกาย มันต้องรับรู้โลกจริงและลงมือทำในโลกจริง นักหุ่นยนต์ยังนิยามคำว่าหุ่นยนต์ไม่ตรงกัน แต่มีสององค์ประกอบที่พูดถึงตรงกันเกือบทั้งหมด (Herath และ St-Onge 2022, บทที่ 1):

  • Intelligence — ไม่ได้แปลว่าฉลาดแบบคน แต่คือตัดสินใจได้เองจากข้อมูลที่มีอยู่จำกัด
  • Embodiment — มีร่างกายจริง ไม่ใช่แค่โปรแกรมในคอมพิวเตอร์

ร่างกายนี่เองที่ทำให้ทุกอย่างยากขึ้น กลอนที่ผิดไปหนึ่งคำ ลบแล้วเขียนใหม่ได้ แต่หุ่นที่ตัดสินใจผิดกลางก้าวล้มไปแล้ว ย้อนกลับไม่ได้ และมันรอนานก็ไม่ได้: Microduck ตัดสินใจใหม่ 50 ครั้งในทุกหนึ่งวินาที เพราะแรงโน้มถ่วงไม่เคยหยุดพัก

ขยับได้ ไม่ได้แปลว่ารับรู้

เป็ดเคยเป็นเครื่องจักรมาก่อนแล้ว ในศตวรรษที่ 18 นักประดิษฐ์ชาวฝรั่งเศสชื่อโวกองซง (Vaucanson) สร้างเป็ดกลที่ดื่มน้ำ ไซ้น้ำ และร้องได้ (Herath และ St-Onge 2022, หมวด 1.4) แต่มันเป็น automaton เหมือนกล่องดนตรีที่เล่นลำดับเดิมทุกครั้ง ถ้ามีลูกบอลกลิ้งมาชน มันก็ทำท่าเดิมต่อไป เพราะมันไม่รับรู้อะไรเลย ส่วน Microduck วัดร่างกายตัวเองและโลกรอบตัวอยู่ตลอด แล้วเปลี่ยนการกระทำตามสิ่งที่วัดได้ นี่คือเส้นแบ่งระหว่างเครื่องกลที่ขยับได้กับหุ่นยนต์

Sense, think, act

วิชานี้มองหุ่นยนต์ทุกตัวเป็นวงจรสามขั้น:

  • Sense: ใช้ sensor วัดโลกหรือวัดร่างกายของตัวเอง
  • Think: ตัดสินใจว่าจะทำอะไร
  • Act: ใช้ actuator เช่น motor ทำให้ร่างกายขยับ พอขยับแล้วโลกเปลี่ยน หุ่นจึงต้องวัดใหม่

ตัวอย่างใกล้ตัวคือหุ่นดูดฝุ่น: กันชนด้านหน้าถูกกดเพราะชนขาโต๊ะ (sense) มันเลือกเลี้ยวขวา (think) แล้วล้อก็หมุนพาตัวเลี้ยวออกไป (act) Microduck ก็เป็นวงแบบเดียวกันแต่เร็วกว่ามาก: IMU ที่วัดว่าลำตัวเอียงไปทางไหน กับมุมของ joint ทุกข้อ, policy ที่ได้จากการเรียนรู้ และ motor 14 ตัวที่ขา คอ และหัว

ทำไมการเดินจึงยาก

Stanford Cart (ปี 1979) ในตำรา หยุดสแกนรอบตัวนาน 15 นาทีทุกครั้งที่วิ่งไปได้หนึ่งเมตร จนข้ามห้องยาว 20 เมตรได้ในห้าชั่วโมง (Herath และ St-Onge 2022, หมวด 1.6) รถหยุดคิดได้ เพราะรถสี่ล้อจอดนิ่งๆ ก็ไม่ล้ม แต่หุ่นสองขาที่หยุดคิดกลางก้าวจะล้มก่อนคิดเสร็จ

การยืนนิ่งก็ไม่ได้แปลว่าไม่ทำอะไร ลองยืนขาเดียวดู ข้อเท้าจะขยับปรับเล็กๆ อยู่ตลอด สิ่งนี้แหละที่ Microduck ตอนต้นคลิปขาดไป: ทุก joint ค้างท่าเดิม แต่ไม่มีอะไรคอยแก้ตอนลำตัวเริ่มเอียง มันจึงล้มที่ 0.86 วินาที และ Lab 3 จะทำให้ล้มแบบนี้อีกครั้ง

สามวิธีเขียนขั้น think

policy ที่ทำให้ Microduck เดินได้มาจากการเรียนรู้ใน simulator คือแถวที่สามของ ตารางที่ 1.1

เส้นทางของวิชา

  1. ร่างกาย (Season 1): หุ่นอยู่ตรงไหน และสั่ง joint ให้ขยับอย่างไร ใน simulator ชื่อ MuJoCo
  2. การเรียนรู้ (Season 2): เขียน agent ที่เรียนจาก reward ขึ้นมาเอง
  3. Microduck (Season 3): train ให้มันเดิน แล้วทดสอบว่ามันทนแค่ไหน

ทำไมเริ่มจาก simulator? เหมือนนักบินที่ฝึกในเครื่องฝึกบินจำลอง ล้มกี่ครั้งก็ไม่มีอะไรพัง และเร่งเวลาให้เร็วกว่าโลกจริงได้มาก การพา policy ที่ฝึกแล้วไปใช้กับหุ่นจริง หรือ sim-to-real เป็นขั้นที่ยากอีกขั้นหนึ่ง ปีนี้วิชาจบที่ simulation ซึ่งไม่ใช่ทางลัด เพราะงาน RL ของหุ่นขาจริงเกือบทุกงานก็ train และคัดกรองใน simulation ก่อนเหมือนกัน เครื่องมือของวิชาคือ Python สำหรับเขียน code, Colab สำหรับรัน notebook บน browser และ Git สำหรับเก็บประวัติทุกครั้งที่แก้ code

ผลที่เห็นใน Lab

Lab 1 — ขับ Microduck ใน browser: ใน simulator ของ Pollen Robotics ปุ่ม W บอกแค่ว่า “อยากเดินหน้า” ส่วนจะยกเท้าไหนและวางตรงไหน policy เลือกเองจากค่าที่ sensor วัดได้ 50 ครั้งต่อวินาที (บนจอขึ้นว่า CTRL 50HZ) ตอนเตะด้วยปุ่ม Q ขาอีกข้างรับน้ำหนักทั้งตัวไว้ข้างเดียว ส่วนท่านั่งและลุกยืนใช้ policy อีกตัวที่ได้จากการเรียนรู้เหมือนกัน

Lab 2 — Python, Git และ Colab: ด้วยตัวเลขของ Microduck dt = 1 / 50 ได้การตัดสินใจทุก 0.02 วินาที, 3000 ครั้งต่อนาที และ 43 ครั้งใน 0.86 วินาทีที่มันล้ม NumPy แปลงมุมขาซ้ายในท่ายืนจาก radian เป็นองศาในคำสั่งเดียว: [0, -5, -26.2, -0.3, 26] แล้ว Git เก็บไฟล์ notes เป็น commit แรก ผ่าน working tree → staging area → repository (Herath และ St-Onge 2022, หมวด 4.8)

Lab 3 — เปิด Microduck ใน MuJoCo แล้วดูมันล้ม: model มี joint 15 ข้อ motor 14 ตัว sensor 6 ตัว joint ที่เกินมาคือ trunk_base_freejoint ซึ่งให้ลำตัวเคลื่อนที่อิสระในโลก จึงไม่มี motor และไม่มี sensor ไหนบอกตำแหน่งเท้าตรงๆ เมื่อค้างท่า STAND ลำตัวค่อยๆ ทรุดจากราว 12 cm แล้วต่ำกว่า 9 cm ที่ 0.86 วินาที ก่อนลงไปอยู่ราว 5 cm พอให้ servo แข็งขึ้น (kp 0.55 → 2.0) จุดต่ำสุดอยู่ที่ 11.5 cm และยืนอยู่ได้ตลอด 1.5 วินาที แต่นั่นแค่ค้างท่าได้ดีขึ้น ยังไม่ได้วัดแล้วแก้ตัวเอง
